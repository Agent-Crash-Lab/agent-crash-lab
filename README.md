# AGENT CRASH LAB

**제조 운영 Agent를 시험하고, 발견한 위험과 근거를 QA 보고서로 제공하는 시스템입니다.**

## 어떻게 사용하는가?

1. 검증할 Agent를 등록하거나 구매·생산·품질 예시를 선택합니다.
2. QA가 제조업 자료를 찾아 새 시험 데이터와 상황 변화를 제안하고, 실행 가능한지 코드로 검사합니다.
3. 시험 환경에서 대상 Agent를 실행합니다.
4. DB·도구·승인 기록을 확인하고 QA 보고서를 저장합니다.

예: **발주는 성공했지만 응답이 끊긴 상황을 만들어, 재시도했을 때 중복 발주하는지 확인합니다.**

## 현재 상태

- **구현됨:** 새 Agent 등록·사용자별 저장, 구매·생산·품질 실행기 선택과 등록부터 실행·판정 연결, 정책 누락 확인·위험 분류·맞춤 시험안, 구매 시험 데이터 변경·실행·DB 판정, 참고 자료 32건의 검색(핵심 근거 28건), 대상 기능에 따른 위험 분류·시험안 생성, 정상 대조·위험 시험의 순차 실행·중단·집계, 검색 출처를 남긴 조사 보고서.
- **앞으로:** 실제 회사 정책·도구·판정기 연결, 실제 LLM 설계 품질 평가, 새 업무 도구·판정기, 조사 중 추가 실험. 생산·품질 외부 HTTP 연결은 구현됐으며 운영자가 실행기와 버전·비용 상한을 설정해야 합니다.

## 실행

최초 `.env`를 준비한 뒤 `make dev-rag-up`으로 자료 확인·색인·전체 개발 서비스를 시작합니다. 첫 실행은 모델과 자료를 내려받습니다. 화면의 **시험 설계 → Agent를 보고 시험 설계**에서 구매·생산·품질 참조 설명으로 시험안을 만듭니다. 화면에서 LLM 생성 또는 기존 시험 예시를 선택합니다. LLM은 키·허용 모델 설정이 필요하며 미설정 시 이유를 표시합니다. 기존 DB 볼륨은 유지합니다.

새 대상은 **평가 대상 → 새 제조업 Agent 등록**에서 입력합니다. 승인·재시도 정책을 모르면 미입력으로 저장하고, 보완 후 시험을 설계합니다. 등록은 설명 분석이며 실제 코드·권한 검증은 아닙니다. 구매·생산·품질 예시 실행기를 명시적으로 선택하고 해당 예시와 같은 도구·정책·입력 형식을 사용하면 실행까지 연결됩니다. 버전이 바뀌면 재등록·재설계합니다. 생산·품질 참조 Agent는 규칙 기반이며 실제 공장 시스템과 연결하지 않습니다. 외부 Agent 연결 계약과 설정은 [시스템 설계](docs/architecture.md#외부-agent-연결)를 참고하세요.
