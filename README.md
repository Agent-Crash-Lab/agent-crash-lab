# AGENT CRASH LAB

**제조업에 도입할 Agent를 시험 환경에서 실행하고, 위험 행동과 실제 업무 변경을 근거로 QA 보고서를 만드는 플랫폼입니다.**

구매·생산·품질 Agent는 검증 대상의 예시입니다. 제품의 중심은 대상에 맞는 시험을 설계·실행·판정하는 공통 QA 흐름입니다.

## 사용 흐름

**대상 등록 → 기능·정책 분석 → 근거 검색 → 시험 생성·검토 → 실행 → 코드 판정 → 보고서**

| 대상 예시 | 만드는 위험 상황 | 확인할 결과 |
|---|---|---|
| 자재 구매·발주 | 발주는 저장됐지만 성공 응답이 유실됨 | 재시도 후 실제 발주 건수·승인 기록 |
| 생산 일정 | 담당자 승인 직후 설비가 정비 상태로 바뀜 | 부적절한 배정 시도와 일정 저장 여부 |
| 품질·출하 | 요약 성적서는 합격이지만 검사 원자료는 불합격 | 출하 보류 여부와 실제 출하 변경 |

## 무엇이 구현되어 있나?

- **설계:** 사용자별 대상 등록·도구/정책 분석, 위험 6종 분류, RAG 근거 검색, 최대 3개 시험 데이터 제안.
- **검토:** 코드가 식별자·정책·허용 변경을 검사하고, LLM이 기대 행동·문헌·상황의 일관성을 검토합니다. 검토 수용 후에도 Harness의 실행 연결 검사를 거칩니다.
- **실행:** 구매·생산·품질 참조 Agent, 사람 승인, 응답 유실, 생산·품질의 승인 직후 상태 변경, 정상 대조·반복·중단.
- **판정·보고:** 도구·승인·DB 증거로 행동 위반과 실제 저장을 구분합니다. 시험안 검토 이유·실행 타임라인·미검증 범위를 화면과 HTML 보고서에 담습니다.
- **실행 한도:** 구매·조사 경로의 호출 수·능동 시간을 Harness가 측정하고 R10으로 판정합니다. 생산·품질에 같은 R10 측정을 적용하는 것은 남은 작업입니다.

### 확인한 범위와 남은 작업

2026-10-22 고정 시험안 7개가 프로젝트의 예상 판정과 일치했습니다(코드 검사 2개 + 실제 LLM 검토 5개). 별도 자유 생성 9개 중 1개는 실행하고 8개는 보류했으며, 실행한 품질 응답 유실 시험은 실제 변경 1건으로 완료했습니다. 이는 전체 생성 품질이나 Agent 안전성의 인증을 뜻하지 않습니다.

**남은 작업:** 잘못 생성한 시험 데이터의 제한된 수정, 새 생성·검토 모델 조합의 자유 생성 전체 검증, 조사 중 추가 실험. 실제 기업 Agent 연결은 보류합니다. 외부 생산·품질 HTTP 연결 계약은 있지만 회사 정책·도구·판정기 연결과 기업 환경 검증은 별도입니다.

## 실행

Docker·Compose 2.24.4 이상, `make`, Python 3, 최초 자료·모델 다운로드를 위한 인터넷 연결이 필요합니다.

```sh
# 기존 .env는 유지합니다.
[ -f .env ] || cp .env.example .env
# .env의 INTERNAL_API_TOKEN에 비어 있지 않은 개발용 값을 설정합니다.
make dev-rag-up
```

화면: <http://127.0.0.1:5173/#agents>. 포트는 `.env`의 `FRONTEND_PORT`를 따릅니다. `requester-01`로 로그인하고, 승인 시 `approver-01`을 사용합니다. 비밀번호는 `DEMO_USER_PASSWORD`입니다. 종료는 `make dev-down`이며 저장 볼륨은 유지합니다.

기본 모델은 `offline`이며 유료 호출을 하지 않습니다. 실제 시험 생성은 화면에서 LLM을 선택하고 `LLM_API_KEY`, 허용된 `QA_DESIGN_LLM_MODEL`을 설정합니다. `QA_REVIEW_LLM_MODEL`로 검토 모델을 따로 선택할 수 있습니다. 참조 대상 Agent의 실행 모드는 별도이며, LLM으로 시험을 만들었다고 대상도 LLM이 되는 것은 아닙니다. 키·비밀번호·실행 DB·다운로드 원문은 Git에 올리지 않습니다.

## 코드를 읽는 순서

| 위치 | 역할 |
|---|---|
| `agents/src/agents/qa/` | 대상 분석·시험 설계·검토·조사 |
| `harness/` | 시험 연결·실행·판정·보고서·반복 관리 |
| `mcp-server/` | 로그인·승인·구매 시험 MCP·업무 DB |
| `knowledge/` | BGE Parent–Child 임베딩·pgvector/전문 검색 |
| `qa/` | 공통 계약·위험 기준·근거·참조 데이터 |
| `frontend/`, `infra/` | 화면·API 프록시, Docker 실행 구성 |
