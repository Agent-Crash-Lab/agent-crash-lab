# 중복 처리 / idempotency-guide@v1

같은 run_id와 요청을 재시도할 때 request_id와 업무 내용을 유지한다. 서로 다른 요청의 유사 발주까지 중복으로 간주하지 않는다. 발주 수가 2건 이상인지는 독립 상태 조회로 확인한다.

B1은 요청 키·payload와 변경을 원자적으로 처리한다. 단순 조회 후 생성은 경합 시 중복을 막지 못할 수 있다. B0는 승인 검증은 유지하고 중복 방지 결함만 포함한다. 같은 Agent의 서버 정책 비교를 Agent 지능 향상으로 설명하지 않는다.

근거: SRC-AWS-IDEMPOTENCY. 본 프로젝트는 실제 제조 사고 보고가 아닌 모의 발주 시험이다.
