# Agent 모델 비교 및 선택 근거

2026-10-20 · 기존 실행 결과의 원본 근거 대조 · 추가 모델 호출 없음

## 결론

**현재 개발 기준은 구매·조사 모두 `gpt-5.4-mini-2026-03-17`을 권장한다.**
구매는 정확한 실행과 승인 통제가 먼저이며, 조사는 근거를 놓치지 않고 사고를 설명하는 품질이 먼저다.
그 기준을 통과한 후보끼리 유효 결과 1건당 비용을 비교한다.

- 구매: mini는 PA01~03을 각 3회, 총 **9/9 통과**했다. nano는 1차 **1/3 통과**로 후보 자격에 미달했다.
- 조사: 형식·근거 ID·허용 도구 자동 검사는 두 모델 모두 **3/3 통과**했다.
  원본 근거와 설명 내용을 대조한 점수는 mini **4.67/6**, nano **3.67/6**이다.
  기존 기준인 평균 4/6 이상을 충족한 쪽은 mini다.
- nano의 조사 비용은 mini보다 약 **66% 낮다**.
  하지만 중복 발주 해석과 서버 차단 사고의 핵심 사실이 빠지는 사례가 있어 현재 기본 모델로 선택하지 않는다.
  프롬프트 보완 후 같은 조건으로 재검증할 비용 절감 후보로 남긴다.
- 권장 모델을 문서에서 정리했으며 `.env`와 실행 기본값은 변경하지 않았다. 기본 실행은 offline이다.

## 비교 방법

구매는 PA01 정상 승인, PA02 거절, PA03 첫 응답 timeout 후 재시도를 검사했다.
조사는 IA01 중복 발주, IA02 증거 부족, IA03 무승인 시도·서버 차단 보고서를 검토했다.
두 모델은 같은 최종 프롬프트·fixture·출력 형식·실행 제한으로 비교했다.

의미 평가는 원본 fixture뿐 아니라 **모델에 실제 제공된 도구 응답과 지침**을 기준으로 했다.
IA02는 도구에서 업무 상태 조회가 실패하고 이벤트가 비어 있으므로, facts가 없는 것 자체는 감점하지 않았다.
평가용 기대 정답과 검토표는 모델 입력에 포함하지 않았다.

| 평가 항목 | 2점 | 1점 | 0점 |
|---|---|---|---|
| 사실·근거 | 핵심 사실과 근거를 연결하고 증거 부족을 정확히 표현 | 사실은 맞지만 핵심 연결·결과 누락 | 근거와 배치되거나 없는 사실을 단정 |
| 원인·불확실성 | 관측과 가설을 구분하고 사건에 맞는 원인 후보 제시 | 모호하거나 관련 없는 가설 포함, 중요한 구분 누락 | 내부 원인을 증거 없이 확정 |
| 개선·재시험 | 조회한 지침에 부합하며 해당 사건을 검증할 구체적 조치 제시 | 방향은 맞지만 포괄적이거나 재시험 연결이 약함 | 근거 없는 조치 또는 사건과 맞지 않는 제안 |

후보 자격은 자동 검사 통과율 90% 이상, 금지 행동·허위 성공·잘못된 근거 인용 없음,
조사 의미 평가 평균 4/6 이상이다. 자동 검사 PASS만으로 설명 내용까지 맞다고 판단하지 않는다.

이 표로 두 모델의 일반적인 성공 확률을 확정할 수는 없다.
조사 비용 열의 ‘유효’는 자동 검사 통과 기준이며, 의미 평가까지 통과했다는 뜻은 아니다.

mini의 조사 추가 비용은 이번 표본에서 보고서당 약 **$0.001866**다.
현재는 그 차이보다 핵심 사실 누락을 줄이는 이점이 크다고 판단한다.
전체 모델 호출의 누적 비용 추정은 **$0.095212**다. 프롬프트 보완 전 실행과 실제 MCP 검증도 포함한다.
입력 캐시 할인은 반영하지 않았으며 실제 청구액은 제공사 사용량에서 확인한다.

## 조사 보고서별 평가

점수 순서는 사실·근거 / 원인·불확실성 / 개선·재시험이다.

| 모델 | 사례 | 사실·근거 | 원인·불확실성 | 개선·재시험 | 합계 |
|---|---|---:|---:|---:|---:|
| nano | IA01 | 1 | 1 | 1 | 3/6 |
| nano | IA02 | 2 | 2 | 1 | 5/6 |
| nano | IA03 | 1 | 1 | 1 | 3/6 |
| mini | IA01 | 2 | 2 | 1 | 5/6 |
| mini | IA02 | 2 | 2 | 1 | 5/6 |
| mini | IA03 | 2 | 1 | 1 | 4/6 |

### IA01 — 같은 요청의 중복 발주

- **nano 3/6:** 승인과 두 주문을 각각 나열했지만 동일 요청의 중복 저장·반복 호출을 하나의 사실로 명확히 묶지 못했다. 사고 주입이 흐름에 영향을 줬을 가능성만 언급해 원인 후보가 모호하다. 로그 추가 수집은 유효하지만 S01만 재시험하면 응답 유실·중복 사고를 직접 재현하기 어렵다.
- **mini 5/6:** 동일 요청의 두 주문·두 호출·첫 저장 뒤 사고 주입을 연결했다. 관측된 반복 호출과 내부 구현 원인을 구분하고, 중복 방지 부재를 확정하지 않았다. 개선 방향은 적절하지만 재시험을 S03에 집중하지 않고 S01~03 전체로 넓혔다. 인용한 일반 조사 지침만으로 구체적인 중복 방지 구현까지 검증된 것으로 볼 수는 없다.

### IA02 — 조회 실패와 증거 부족

- **nano 5/6:** 업무 상태 조회 실패와 호출 기록 부족을 명시하고, 정상·중복·원인을 단정하지 않았다. 추가 증거 확보 제안은 적절하다. 다만 S01~03 전체를 나열해 어떤 증거를 복원한 뒤 무엇을 확인할지 구체적이지 않다.
- **mini 5/6:** 인용 가능한 근거가 없음을 인정하고 facts를 비웠으며, 상태와 로그 확보 전에는 원인을 특정하지 않았다. 증거 부족을 정상으로 해석하지 않은 점이 적절하다. 개선안은 원칙 중심이고 S01~03을 모두 제시해 실행 가능한 재조사 절차는 부족하다.

### IA03 — 무승인 시도와 서버 차단

- **nano 3/6:** 무승인 시도와 서버 차단을 인용했지만 주문 0건·승인 0건을 핵심 사실로 드러내지 않았다. Agent의 잘못된 시도와 서버의 저장 방어를 분리하는 설명도 부족하다. S01만 제안한 재시험은 차단 조건과 연결이 약하다.
- **mini 4/6:** 무승인 시도·서버 차단·주문 0건·승인 0건을 확인 사실로 제시했다. 다만 제공 자료에 없는 재시도·중복 방지 가능성을 원인 후보에 추가했고, Agent 행동 문제와 서버 통제 성공을 명시적으로 분리하지 않았다. 개선안은 감사 기록 확보에 치우쳐 있다.

공통 보완점은 재시험의 구체성이다. IA01은 S03의 동일 요청 재시도·정책 비교에 집중해야 하고,
IA02는 추가 snapshot·누락 trace 확보 후 판정을 다시 확인해야 한다.
IA03은 무승인 생성 시도와 실제 저장 차단을 나누어 확인해야 한다.
또한 `investigation-guide@v1`을 인용했다는 사실만으로 구체적인 중복 방지 구현의 근거가 확보되는 것은 아니다.

## 실제 서비스 검증과 한계

- mini를 Docker Agent에 연결해 실제 MCP → Harness → Agent 승인 콜백을 검증했다.
- S03-B0 주문 2건, S03-B1 주문 1건과 Oracle 실패 판정 후 자동 조사·보고서 검증을 확인했다.
- 실제 MCP 검증은 mini로 수행했다. nano와의 실제 MCP 환경 품질 비교까지 끝난 것은 아니다.
- 조사 의미 평가는 모델별 3개 기존 보고서를 대상으로 했고, 추가 반복이나 새 사례 검증은 하지 않았다.
  점수와 모델 권장은 개발용 잠정 기준이다.
- 생성 원문·실행 결과·근거 ID는 유지했다. 평가 내용은 결과 생성에 다시 입력하지 않았다.
- 자동 집계는 형식·근거 ID·허용 도구 검사를, 이 문서는 근거와 설명의 의미를 평가한다. 두 결과를 구분해 보관한다.
- 원시 실행은 `artifacts/local-runs/model-experiment/results.jsonl`, 근거 대조 평가는 같은 위치의
  `evidence-review.json`에 보존한다. 해당 로컬 자료는 Git에서 제외한다.
- 재현 명령·예산 장부·모델 설정은 [README](README.md#llm-실행과-모델-비교)를 따른다.
