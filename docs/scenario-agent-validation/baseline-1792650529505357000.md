## 측정 가능한 지표

- 실행 연결 수율: 1/3 = **33.3%**. 이는 실행 준비율이며 시나리오 타당도 점수가 아닙니다.
- 코드 사전검사 통과율: 2/3 = **66.7%** (수용 및 근거 보류는 구조 검사에서 거절되지 않은 제안으로 계산).
- 제조 근거 보류율: 1/3 = **33.3%**.
- 출력 품질 12점 점수표: 당시에 고정 평가표가 없어서 이 기준표를 사전 적용한 값은 아닙니다. 제안 3은 아래의 단일 검토자 예비 재채점만 기록합니다. 나머지 두 제안은 구조/근거 결함으로 보류되어 내용 품질 전 항목 점수를 산출하지 않았습니다.

### 제안 3의 사후 예비 채점

이번에 만든 기준표를 기존 기록에 시험 적용한 **단일 검토자의 예비 채점**입니다. 독립 평가자 2인의 점수도, 당시 실험의 사전 정의 점수도 아닙니다.

| 업무 목표 | 형태학 적용 | 실행 정합성 | 제조 근거 | Agent 실패 경로 | 사실/가설 분리 | 합계 |
|---:|---:|---:|---:|---:|---:|---:|
| 2 | 1 | 2 | 0 | 1 | 1 | **7/12** |

판정은 **보류**입니다. 승인 거절 상태와 실행 데이터는 모의 실행 가능하지만, 제조 검토의 `TECH-NIST-OT`는 제안한 승인 우회가 초래할 구체적인 제조 결과를 입증하지 않습니다. `RES-AGENT-SAFETY`도 일반 실패 유형을 뒷받침할 뿐, 해당 참조 Agent의 `assign_operation` 권한과 실제 시도 경로를 검토 이유에서 확인하지 않았습니다. 따라서 총점 자체보다 제조 근거 0점과 핵심 근거 기준 미달이 결정적입니다. 이 재채점은 “현재 구현이 이미 두 관점에서 구체적으로 평가한다”는 기존 인상을 수정하는 근거입니다.

## 무엇이 부족했나

실행 가능한 샘플에서 제조 단계는 “승인 후 일정 변경”과 제조 현장 결과 사이의 인과를 보이지 않고 승인 정책을 반복했습니다. 인용 문서 `TECH-NIST-OT`는 OT 보안 지침이지 이 제안에서 설명한 생산 일정 사고의 실증 자료가 아닙니다. Agentic 단계는 `RES-AGENT-SAFETY`를 인용했으나, 이 제안의 실제 도구/권한 실패 경로를 특정하지 않았습니다. 그러므로 1개 수용은 검토 파이프라인 통과로만 기록하며 두 관점이 충분히 타당했다고 해석하지 않습니다.

다음 재평가는 `test-cases.json` 전체로 동일한 target/morphology/knowledge snapshot과 모델 버전을 고정해 진행합니다. 각 proposal마다 6개 항목을 0–2점으로 두 평가자가 채점하고, 실행 가능한 제안 비율·두 근거 모두 적합한 비율·허위/무관 인용률·평가자 일치율을 따로 보고합니다. 당시 고정 데이터셋 출력이 보존되어 있지 않아 12개 기준 케이스에 대한 사후 모델 점수는 복원할 수 없습니다.
